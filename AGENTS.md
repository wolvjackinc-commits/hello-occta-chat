- Broadband availability is supplier-neutral: `_shared/networkEvidence.ts` is the only gate for binding contract speeds — why: no live supplier feed, so documents must never be issued from guessed speeds.
- Never mark an invoice, DD collection or retry as paid unless the money is fully confirmed received (verified webhook, bank-received date, or an admin confirming it) — why: "Unpaid"/returned/re-presented DDs were read as paid (Oct 2026), hiding real arrears; when unsure, leave it unpaid.
- OCCTA takes payment by Direct Debit or bank transfer ONLY — no card, pay-by-phone or online "Pay now" checkout. `_shared/paymentOptions.ts` holds the bank details and labels; every invoice, email, reminder, dashboard screen and chat answer must use it — why: card/phone payment was retired (Oct 2026) and customers were still being told to pay that way.
- Crawlable public HTML comes from `seo-snapshots/` (rendered in Chrome by the "SEO Snapshots" GitHub workflow, baked in by `vite-plugin-seo-snapshots.ts`) — why: Lovable publishes without Chrome, so pages otherwise ship to crawlers as an empty shell. Never hand-edit snapshots; run the workflow after content changes.
- Admin-built consumer broadband quotes get contract prerequisites only via `supabase/functions/_shared/manualQuoteContract.ts` (exact plan-cap estimate, customer-chosen service date, benchmark-capped cease wording; send blocked otherwise) — why: these quotes have no Journey 2 session and were sent un-issuable (Nov 2026).
- Abandoned-checkout emails are sent by BOTH `process_checkout_tracking()` (SQL) and `journey2-resume-email`; every "don't email" rule (signed contract, do-not-contact `recovery_opt_out_at`, existing customer, suppressed, test) must be in both — why: the SQL sender lacked the signed-contract and existing-customer checks and emailed 16 signed customers (Aug–Oct 2026).
